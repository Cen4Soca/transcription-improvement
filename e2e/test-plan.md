# Playwright E2E テスト計画

## 概要

Transcription Review App のエンドツーエンドテスト計画。  
Amazon Transcribe が生成した文字起こし結果を人間の校閲者が確認・修正する Web アプリケーションの主要機能を網羅する。

### テスト対象 URL

| ルート | ページ | 対象ロール |
|--------|--------|-----------|
| `/` | 校閲セッション一覧 | 全ロール |
| `/sessions/:sessionId` | 校閲画面 | 全ロール |
| `/upload` | メディアアップロード | 全ロール |
| `/language-models` | カスタム言語モデル管理 | Admin, TeamLeader |
| `/ranking` | コントリビューターランキング | 全ロール |
| `/admin` | 管理画面 | Admin |

### テスト環境

- ベース URL: 環境変数 `BASE_URL` で設定
- テストユーザー: Cognito に事前登録された 3 ロール分のユーザー
- シードファイル: `frontend/src/App.tsx`

## テスト実行設定

### 環境変数

```
BASE_URL=http://localhost:5173
TEST_USER_ADMIN_EMAIL=admin@example.com
TEST_USER_ADMIN_PASSWORD=****
```

> **注意**: TeamLeader / Reviewer ユーザーは事前登録不要。テスト実行時に Admin ユーザーで動的に作成し、全テスト完了後に削除する。

### テストユーザーのライフサイクル

テスト全体を通じて以下の流れでユーザーを管理する：

```
globalSetup (テスト開始前)
  ├─ Admin でログイン
  ├─ Admin API 経由で TeamLeader ユーザーを作成
  ├─ Admin API 経由で Reviewer ユーザーを作成
  ├─ 作成したユーザー情報を共有ストレージ (JSON) に保存
  └─ 必要に応じてチーム作成・メンバー割り当て

テスト実行
  ├─ 各テストは共有ストレージからユーザー情報を読み取り
  └─ ロール別テストで適切なユーザーでログイン

globalTeardown (テスト完了後)
  ├─ Admin でログイン
  ├─ Admin API 経由で Reviewer ユーザーを無効化・削除
  ├─ Admin API 経由で TeamLeader ユーザーを無効化・削除
  └─ テスト中に作成したチーム等のクリーンアップ
```

#### globalSetup で作成するユーザー

| ロール | メール (生成規則) | 表示名 |
|--------|------------------|--------|
| TEAM_LEADER | `e2e-leader-{timestamp}@test.example.com` | E2E テストリーダー |
| REVIEWER | `e2e-reviewer-{timestamp}@test.example.com` | E2E テストレビュアー |

- タイムスタンプ付きメールで並列実行時の競合を回避
- 作成直後に初回パスワード変更（NEW_PASSWORD_REQUIRED チャレンジ対応）を実施
- 共有ストレージ: `.auth/test-users.json` に保存（`.gitignore` 対象）

### テストフィクスチャ（前提条件）

- Cognito に Admin ユーザーのみ事前登録済み（TeamLeader / Reviewer は globalSetup で作成）
- DynamoDB に以下のシードデータが投入済み:
  - 複数ステータスの ReviewSession（最低 60 件 — ページネーション検証用）
  - MediaFile（音声・動画）
  - Transcription（複数セグメント）
  - Correction データ
  - Team + メンバー割り当て
  - ランキングデータ（最低 30 件）
  - IP Allowlist エントリ
  - 監査ログ

### 実行コマンド

```bash
cd frontend
npx playwright test
npx playwright test --project=chromium
npx playwright test --grep "認証"
```
