# Custom language model team isolation and management

Introduces team ownership for Amazon Transcribe custom language models, which were previously an account-global resource with no app-side owner, closing three leak paths: unrestricted model-name enumeration, cross-team model use in jobs, and ingestion of other teams' sessions as training data. A two-layer design keeps the immutable Transcribe model as the source of truth and stores team ownership, a human-readable display name, and lifecycle state in a DynamoDB metadata record. On top of isolation it adds display-name edit, ADMIN teamId re-assignment for reorganizations, and an idempotent soft-then-hard delete, with the frontend reworked to require a team + display name on create and to surface delete/rename/team-change/PENDING-recovery.

Watch for: a minor audit-filter gap — the three new `LANGUAGE_MODEL_*` audit operation types are written to records but are not added to the `GET /admin/audit-logs` `operationType` filter allowlist, so an ADMIN cannot filter by them (confirmed). The single-model status endpoint `GET /language-models/{modelName}` still has no per-team access check, but that handler is unchanged by this PR and is pre-existing/out of scope (confirmed). Everything else — GSI3 + GSI1/GSI2 ride-on, create flow, team-scoped list, job-usage check, delete ordering/idempotency, and all five required property tests — is implemented and verified green.

**Verdict**: APPROVED

## High-level view

The isolation model rides the existing single table: a new GSI3 (fixed partition `LANGUAGEMODEL`) backs the ADMIN full-list, while GSI1 (`TEAM#{teamId}` / `LANGUAGEMODEL#{modelName}`) and GSI2 (`TEAM#{teamId}#DISPLAYNAME` / `{displayNameLower}`) are reused through distinct, previously-unused key prefixes/partitions, so language-model items are invisible to existing media/session/audit/job queries. The repository encodes those keys in one place and the ride-on non-collision is asserted at the repository test level.

The create flow is the ingestion gate: TEAM_LEADER+, destination team must exist, non-ADMIN must be a member, every source session must pass `checkSessionAccess`, display name is trimmed/1–100/within-team-unique, and a Transcribe `LimitExceededException` (or HTTP 429) is mapped to a dedicated `QUOTA_EXCEEDED` 429. The two runtime leak paths are closed by `checkLanguageModelAccess` (404-hides existence): list is the intersection of team-scoped metadata (ADMIN=GSI3, others=GSI1 union) with Transcribe `COMPLETED`, excluding PENDING; job start resolves model access before any Transcribe call and records a job-start audit log carrying `languageModelName` and, for ADMIN cross-team use, `crossTeamModelUsage`.

Lifecycle operations mirror the session-name edit convention. Display-name edit enforces the same ownership + within-team uniqueness (excluding self); teamId re-assignment is ADMIN-only with destination-exists and destination-collision guards and rewrites the dependent GSI keys. Delete is a strict soft(PENDING)→Transcribe→S3→hard sequence, each step idempotent with bounded retry; a later-step failure leaves the record PENDING so a re-invoked DELETE resumes and skips the eligibility gates, with in-use/in-training checks sourced authoritatively from Transcribe `ListTranscriptionJobs`/`DescribeLanguageModel`.

The infra wiring is least-privilege: the rename and team-change Lambdas get DynamoDB + KMS only, and delete adds S3 `DeleteObject` scoped to `training-data/*` plus exactly four Transcribe actions. The frontend requires a team selector (ADMIN all / TEAM_LEADER own via `GET /me/teams`) and display name on create, shows display name as the job-form option label while still submitting `modelName`, and renders quota errors in Japanese; vitest-axe assertions are retained in the touched component tests. Requirements 18/20 are revised and 20A/20B/20C added, in Japanese.

<summary>Details</summary>

### GSI3 plus GSI1/GSI2 ride-on

The ride-on is realized through non-overlapping key spaces rather than new indexes for every access pattern. The language-model item sets `GSI1SK = LANGUAGEMODEL#{modelName}` under the shared `TEAM#{teamId}` partition, and `queryByTeam` filters with `begins_with(GSI1SK, 'LANGUAGEMODEL#')`, so it cannot surface in the existing `MEDIA#`/`SESSION#` team queries, and `getUserTeamIds` (which reads `GSI1PK=USER#{userId}`) touches a different partition entirely. Uniqueness rides GSI2 on `TEAM#{teamId}#DISPLAYNAME`, a partition no other producer writes. Only GSI3 is genuinely new, keyed on the fixed `LANGUAGEMODEL` partition for the ADMIN full scan. The repository centralizes these keys in a single `KEYS`/`toItem` map and the non-collision prefix is asserted in the repository test, which is the right place to catch a future accidental prefix change.

### Create as the ingestion gate

`createModel` runs ownership before side effects: role, team-exists, membership (ADMIN exempt), then `checkSessionAccess` for every `sessionId` — so an other-team session yields 404 before any S3 upload or Transcribe call. Within-team uniqueness is checked against `findByDisplayName(teamId, lower)` and the Transcribe create is wrapped so a `LimitExceededException`/`ThrottlingException`/`TooManyRequestsException` or any HTTP 429 becomes `quotaExceededError` (429, `QUOTA_EXCEEDED`). One ordering note, non-blocking: the handler's `fetchConfirmedSegments` reads segment text from the requested sessions before the service runs `checkSessionAccess`, so unauthorized session content is briefly loaded into memory even though it is never returned and the request is rejected 404. Moving the per-session check ahead of the fetch would tighten this, but there is no data exposure as implemented.

### Runtime leak closure: list and job usage

`checkLanguageModelAccess` is the shared guard — missing or PENDING or other-team all collapse to `denyResourceAccess()` (404). List returns only the intersection of the caller-visible metadata set and Transcribe `COMPLETED`, which means a model present in Transcribe but without metadata (or soft-deleted) is never shown. `startJob` calls the guard before any Transcribe interaction, so an inaccessible `languageModelName` fails closed with 404; the cross-team flag is computed only for ADMIN against `getUserTeamIds`. The job-start audit is recorded for every start, with `languageModelName`/`crossTeamModelUsage` added only when relevant — this is a new audit record type (`TRANSCRIPTION_JOB_STARTED`) kept in sync across both operation-type unions and the audit-logs allowlist.

### Delete ordering and idempotent recovery

The sequence and its failure semantics are the subtle part, and the property test pins them down: soft-delete is always first; the deduped milestone order is strictly soft → transcribe → s3 → hard; a persistent later-step failure leaves the record PENDING, records no success audit, and rethrows; a re-invocation on a PENDING record skips the `DescribeLanguageModel`/`ListTranscriptionJobs` eligibility gates (asserted via `describeCalled`/`listCalled` false) and converges to hard-delete + `LANGUAGE_MODEL_DELETED`. Already-absent Transcribe models and S3 objects are treated as success through `isNotFoundError`, which is what makes re-runs safe. In-use/in-training detection is sourced only from Transcribe (`ListTranscriptionJobs` with a `GetTranscriptionJob` fallback when the summary omits the model name), matching the decision to treat Transcribe as authoritative rather than DynamoDB.

### Audit filter allowlist gap

`backend/src/handlers/audit-logs.ts` validates the `operationType` query parameter against `VALID_OPERATION_TYPES`. This PR adds `TRANSCRIPTION_JOB_STARTED` to that list but not the three `LANGUAGE_MODEL_*` lifecycle types it also introduces, so an ADMIN who filters the audit log by `LANGUAGE_MODEL_DELETED`/`_TEAM_CHANGED`/`_NAME_CHANGED` gets a 400 "invalid operation type". The records are written and appear in the unfiltered, paginated listing, so this is a filter-completeness miss rather than an audit-integrity problem — but since the whole point of these audit types is after-the-fact review of team re-assignments and deletions, the filter should accept them.
